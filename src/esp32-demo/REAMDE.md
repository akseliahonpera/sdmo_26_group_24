# ESP32 emulation which can connect to other docker services

## Goal

```text
ESP32 guest
   |
   | 10.0.2.2:8080
   v
QEMU SLIRP
   |
   v
esp32 Docker container :8080
   |
   | socat
   v
main-service:8080
   |
   v
HTTP 200 OK
```
---

# Step 1 — Install Docker

Install Docker Desktop or Docker Engine.

Then check:

```bash
docker --version
```

You should get something like:

```text
Docker version 28.x
```

---

# Step 2 — Check project structure

All files are already created for demo scenario

```text
esp32-demo/
├── backend/
├── Dockerfile
├── docker-compose.yml
└── firmware/
```
---

# Step 3 - Build and start docker services

Build and start docker containers:
```bash
docker compose up --build
```
(This may take a while the first time.)

Check running containers:
```bash
docker container ps 
```

Should result:
```log
CONTAINER ID   IMAGE          COMMAND                  CREATED          STATUS          PORTS                                         NAMES
0de30575d038   971948df024f   "/opt/esp/entrypoint…"   17 minutes ago   Up 10 seconds                                                 esp32-demo-esp32-1        
241d0dd0a9c1   8f662e804474   "python server.py"       44 minutes ago   Up 10 seconds   0.0.0.0:8080->8080/tcp, [::]:8080->8080/tcp   esp32-demo-main-service-1
```

---

# Step 4 - Check esp32 emulation container

Run:
```bash
docker exec -it esp32-demo-esp32-1 bash
```

If this fails check container name i.e. "esp32-demo-esp32-1" from previous step and use that.

You should now be inside the container:

```text
root@...:/workspace#
```

Enable idf tools:
```sh
source /opt/esp/idf/export.sh
idf.py --version
```

Check QEMU:

```bash
qemu-system-xtensa --version
```

---

# Step 5 — Build the firmware

**Inside the esp32 container**:

Move to firmware dir:
```bash
cd firmware
```

Set the target:
```bash
idf.py set-target esp32
```

Build:
```bash
idf.py build
```

If successful, you should have:
```text
firmware/
└── build/
    ├── bootloader/
    │   └── bootloader.bin
    ├── partition_table/
    │   └── partition-table.bin
    ├── temperature_sensor.bin
    ├── flash_args
    └── ...
```

---

# Step 6 - Create a QEMU-compatible flash image

From:

```text
/workspace/firmware
```

Create `flash.bin`:
```bash
idf.py merge-bin -o flash.bin --fill-flash-size 4MB
```

This uses the flash arguments generated by ESP-IDF and pads the resulting image to exactly **4 MB**.

You should see output similar to:

```text
Wrote 0x400000 bytes to file build/flash.bin
```

Verify the file:
```bash
ls -lh build/flash.bin
```

Expected:
```text
-rw-r--r-- 1 root root 4.0M Sep 27 09:15 build/flash.bin
```

You now have:
```text
/workspace/firmware/build/flash.bin
```
with a QEMU-supported 4 MB size.

---

# Step 7 - Start traffic forwarding from QEMU to external docker service


Start socat first to forward traffic to the dummy backend service

```bash
socat TCP-LISTEN:8080,bind=0.0.0.0,reuseaddr,fork TCP:main-service:8080 &

socat TCP-LISTEN:8080,bind=0.0.0.0,reuseaddr,fork TCP:edge-gateway:7777 &
```

Depending on the final setup change the fork target accordingly
```bash
socat TCP-LISTEN:8080,bind=0.0.0.0,reuseaddr,fork TCP:<Docker service name>:<Docker service port> &
```

# Step 8 - Start ESP32

Start ESP32 sim from create flash and attach it to OpenEth network device:

```bash
qemu-system-xtensa \
    -nographic \
    -icount 3 \
    -machine esp32 \
    -drive file=build/flash.bin,if=mtd,format=raw \
    -nic user,model=open_eth,id=lo0
```

You should eventually see:

```text
...
I (1643) main_task: Returned from app_main()
I (2643) qemu_device: Got IP: 10.0.2.15
I (2643) qemu_device: Gateway: 10.0.2.2
I (2643) qemu_device: Netmask: 255.255.255.0
I (2643) esp_netif_handlers: eth ip: 10.0.2.15, mask: 255.255.255.0, gw: 10.0.2.2
I (6643) qemu_device: GET http://10.0.2.2:8080/health
I (6643) qemu_device: HTTP status=200 content_length=3
```

Now ESP32 simulation is running and it is successfully calling another docker containers service.

**To stop QEMU execution `Ctrl + A, then X` in the terminal.**
